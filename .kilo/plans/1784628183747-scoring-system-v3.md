# Plan: GitRanked Scoring System v3

## Goal

Replace the v1/v2 raw-event scoring (`src/lib/scoring.ts`: `WORK_TYPE_MULTIPLIER` + `linesBonus`/`filesBonus` + per-event `classification`) with a deterministic, fact-driven, multi-unit scoring architecture: GitHub events → `work_unit_candidates` → AI fact-extraction of 1-N work items per candidate → pure `facts → derived` rule engine → pure Layer-2 scoring engine → `dimension_scores` (current + all_time). AI supplies structured *facts* only; difficulty/impact/execution/novelty/risk/value are computed by config-driven rules. `extraction_confidence` affects admin review routing only, never the score. `size_metrics` are audit/heuristic-fallback only, never scored. Work type categorizes; it is never a multiplier.

## Confirmed decisions (from interview)

1. **Vitest** added as devDependency + `test`/`typecheck` scripts. The deterministic core (facts→derived, Layer-2 engine) is pure and tested with hand-written fixtures — no AI, no DB — exactly as the spec requires.
2. **Replace the score shape, update consumers.** v3 `dimension_scores` (`impact/quality/collaboration/consistency/composite` + `decay_profile`) becomes the source of truth. Update the repo leaderboard page, compare page, `/scores` route, and OG leaderboard route. Delete `computeContributionScore`/`normalizeScoreToImpact`/`WORK_TYPE_MULTIPLIER` after parity check.
3. **Fully replace per-event `classification`; rewire narratives.** Retire `github_events.classification` as a scoring input AND as the narrative signal. `work_units.work_type` + `facts` become the single classification source for both scoring and the 5 narrative AI tasks (`repository_summary`, `weekly_report`, `monthly_report`, `team_insights`, `contributor_profile`/`impact_analysis`). Rewire `src/lib/ai/context.ts` + `src/lib/ai/fallback.ts` to read from `work_units` joined to events, not `e.classification`.
4. **Outcome enrichment is lazy-on-read.** When the leaderboard/detail page is rendered and a contributor's shipped `work_units` have `outcome IS NULL` or stale (`outcome_updated_at` older than a tunable), enrich inline, write back, and rescore that contributor. No cron, no webhook host. First load pays the cost; cache subsequent reads. (Choice makes no `vercel.json` cron needed.)
5. **Pushes are segmented into work_units too.** Extend the push webhook payload to store `before`/`after`/`head_sha`; add a compare-commits diff fetch (`/repos/{owner}/{repo}/compare/{before}...{after}`) reusing `deriveDiffFactsFromFiles`. Legacy push events lacking `before`/`after` still feed Consistency and are marked `needs_reclassification` (heuristic/commit-message fallback, or skipped from work-unit extraction with a logged reason).

## Decisions made (tech — veto-able, stated for review)

- **`raw_events` = `github_events`** (keep the existing table name; the spec's `raw_events` is this table). Work units reference source events via `source_event_ids int[]`.
- **Attribution MVP = single author** = the `github_events.contributor_id` already stored, `attribution_weight = 1.0`. The `work_unit_contributors` table is built multi-author-ready (sums to 1) but populated 1:1 for now. Co-authors are not captured by the current webhooks — out of scope.
- **Candidate `correlation_key` conventions:**
  - PR: `pr:{repo_id}:{pr_number}` — created on `pr_merged`.
  - Push: `push:{repo_id}:{after_sha}` — created on `push`.
  - Review: `review:{repo_id}:{pr_number}:{review_id}` — created on `review_submitted` (one Review work_unit per review).
  - Issue: `issue:{repo_id}:{issue_number}` — created on `issue_closed` (issue-close as a lightweight unit; may yield 0-1 work units).
  - Re-extract only when `status = 'needs_reclassification'` (admin trigger, or `derivation_ruleset_version` bump on the candidate).
- **`scoring_config`** holds presets keyed by `(profile, version)` with `repo_id` always NULL for the 5 presets (global default = `balanced`). A repo selects its profile via a new `repositories.scoring_profile VARCHAR` (NULL → `balanced`). Per-repo weight overrides are out of scope.
- **Explainability is a pure `facts → rationale` template function** (`impact_reason` / `quality_reason`), generated from which facts are true — never a separate AI free-text call.
- **Confidence policy = spec verbatim:** `extraction_confidence >= 0.6` → `extraction_source='ai'`; `< 0.6` → run heuristic fact-correction → `extraction_source='ai_facts_corrected'`, `flagged_for_review=true`. Confidence never scales any score. No AI key at all → `extraction_source='heuristic_fallback'` (facts from diff paths + word-boundary title heuristics).
- **Decay model:** `decay_weight(unit, as_of, half_life) = exp(-age_days / half_life)`. `current` profile applies decay over **all** shipped units as_of `now` (no hard window cutoff; the half-life makes old units negligible). `all_time` uses weight 1 over all shipped units. `window_start`/`window_end` = min(`shipped_at`)..`now` for audit display. `decay_half_life_days` default **60** (tunable via `scoring_config`).
- **`derived` is pure facts→numbers, frozen at classification.** `derived.execution_quality` (frozen) = `clamp(1..5, 1 + testing_added + documentation_updated)` (max 3 from facts alone). The cross-PR **review-outcome bump** is applied **at Layer 2** to the *Quality contribution* only: `final_execution = clamp(1..5, frozen + bump)` where `bump ∈ {-1,0,+1}` from sibling Review work_units on the same PR (blocking-issue-found-and-fixed or clean approval → +1; unresolved blocking review → -1; else 0). `value` (Impact dimension) uses frozen `derived` only. This keeps `facts→derived` independently unit-testable; the review bump is an integration test.
- **Heuristic fallback uses word-boundary regex** (`\b…\b`), not `String.includes` — fixes the "debug" matches "bug" class of bug from v1/v2. Reuse/extend the path patterns already in `src/lib/ai/diff-facts.ts` (`TEST_PATTERNS`, `MIGRATION_PATTERNS`, `DOC_PATTERNS`) and add `AUTH_PATTERNS`, `DISTRIBUTED_STATE_PATTERNS`, etc. for fact-correction.
- **Malformed `created_at` guard:** every `Date` parse checks `Number.isFinite(date.getTime())` before use; bad events are skipped for scoring but never crash the contributor's batch (spec known-bug). Push `before`/`after` SHAs validated before compare-commits fetch.

## Data model (new — via idempotent `initSchema()` additions in `src/lib/db.ts`)

All new datetime columns `TIMESTAMPTZ`. Arrays via `INTEGER[]` / `JSONB`. Keep `github_events` as raw_events.

```sql
CREATE TABLE IF NOT EXISTS work_unit_candidates (
  id BIGSERIAL PRIMARY KEY,
  repo_id INTEGER NOT NULL REFERENCES repositories(id),
  correlation_key VARCHAR(160) NOT NULL,   -- pr:{repo}:{num} | push:{repo}:{sha} | review:{repo}:{num}:{reviewId} | issue:{repo}:{num}
  status VARCHAR(24) NOT NULL DEFAULT 'pending',  -- pending | classified | needs_reclassification
  source_event_ids BIGINT[] NOT NULL DEFAULT '{}',
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  classified_at TIMESTAMPTZ,
  UNIQUE (repo_id, correlation_key)
);
CREATE INDEX IF NOT EXISTS wuc_repo_status_idx ON work_unit_candidates(repo_id, status);

CREATE TABLE IF NOT EXISTS work_units (
  id BIGSERIAL PRIMARY KEY,
  repo_id INTEGER NOT NULL REFERENCES repositories(id),
  candidate_id BIGINT NOT NULL REFERENCES work_unit_candidates(id),
  work_type VARCHAR(24) NOT NULL,           -- Feature|BugFix|Refactor|Performance|Security|Documentation|Testing|Infrastructure|Review
  facts JSONB NOT NULL,                      -- extracted fact schema (or Review fact schema)
  derived JSONB NOT NULL,                    -- {difficulty,impact,execution_quality,novelty,risk,value}
  derivation_ruleset_version VARCHAR(24) NOT NULL,
  extraction_confidence REAL NOT NULL DEFAULT 0,
  extraction_source VARCHAR(24) NOT NULL,   -- ai | heuristic_fallback | ai_facts_corrected
  flagged_for_review BOOLEAN NOT NULL DEFAULT false,
  shipped BOOLEAN NOT NULL DEFAULT false,
  outcome JSONB,
  outcome_updated_at TIMESTAMPTZ,
  size_metrics JSONB,                        -- {additions,deletions,changed_files} audit-only
  rationale JSONB NOT NULL,                  -- {impact_reason,quality_reason}
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  shipped_at TIMESTAMPTZ,
  source_event_ids BIGINT[] NOT NULL DEFAULT '{}'
);
CREATE INDEX IF NOT EXISTS wu_repo_contrib_idx ON work_units(repo_id);
CREATE INDEX IF NOT EXISTS wu_shipped_idx ON work_units(repo_id, shipped_at) WHERE shipped = true;
CREATE INDEX IF NOT EXISTS wu_review_queue_idx ON work_units(repo_id, flagged_for_review) WHERE flagged_for_review = true;
CREATE INDEX IF NOT EXISTS wu_outcome_idx ON work_units(repo_id, shipped_at) WHERE shipped = true AND outcome IS NULL;

CREATE TABLE IF NOT EXISTS work_unit_contributors (
  work_unit_id BIGINT NOT NULL REFERENCES work_units(id) ON DELETE CASCADE,
  contributor_id INTEGER NOT NULL REFERENCES github_contributors(id),
  attribution_weight REAL NOT NULL,          -- sums to 1 per work_unit
  PRIMARY KEY (work_unit_id, contributor_id)
);
CREATE INDEX IF NOT EXISTS wuc_contrib_idx ON work_unit_contributors(contributor_id);

CREATE TABLE IF NOT EXISTS work_unit_overrides (
  id BIGSERIAL PRIMARY KEY,
  work_unit_id BIGINT NOT NULL REFERENCES work_units(id),
  field VARCHAR(40) NOT NULL,
  value JSONB NOT NULL,
  overridden_by INTEGER REFERENCES app_users(id),
  reason TEXT,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX IF NOT EXISTS wuo_unit_idx ON work_unit_overrides(work_unit_id);

CREATE TABLE IF NOT EXISTS scoring_config (
  id BIGSERIAL PRIMARY KEY,
  version VARCHAR(24) NOT NULL,
  repo_id INTEGER REFERENCES repositories(id),    -- NULL = preset/global
  profile VARCHAR(24) NOT NULL,                    -- balanced|product|infrastructure|open_source|research
  derivation_weights JSONB NOT NULL,
  value_weights JSONB NOT NULL,                    -- {impact,execution,difficulty}
  caps JSONB NOT NULL,
  decay_half_life_days INTEGER NOT NULL DEFAULT 60,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  UNIQUE (version, profile, repo_id)
);

CREATE TABLE IF NOT EXISTS dimension_scores (
  contributor_id INTEGER NOT NULL REFERENCES github_contributors(id),
  repo_id INTEGER NOT NULL REFERENCES repositories(id),
  window_start TIMESTAMPTZ,
  window_end TIMESTAMPTZ,
  decay_profile VARCHAR(16) NOT NULL,             -- current | all_time
  impact REAL NOT NULL DEFAULT 0,
  quality REAL NOT NULL DEFAULT 0,
  collaboration REAL NOT NULL DEFAULT 0,
  consistency REAL NOT NULL DEFAULT 0,
  composite REAL NOT NULL DEFAULT 0,
  scoring_config_version VARCHAR(24) NOT NULL,
  computed_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  PRIMARY KEY (contributor_id, repo_id, decay_profile, scoring_config_version)
);

CREATE TABLE IF NOT EXISTS classification_cache (
  content_hash VARCHAR(64) PRIMARY KEY,            -- sha256(diff + derivation_ruleset_version)
  response JSONB NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

ALTER TABLE repositories ADD COLUMN IF NOT EXISTS scoring_profile VARCHAR(24);
ALTER TABLE github_events ADD COLUMN IF NOT EXISTS before_sha VARCHAR(40);
ALTER TABLE github_events ADD COLUMN IF NOT EXISTS after_sha VARCHAR(40);
```

Note: v3's `work_type` enum drops the v2 `Database/API/Frontend/Backend/Other` noise (those were surface areas, not work types) and uses the spec's 9-value set. Narrative tasks that grouped by `work_type` must map legacy→new where they read historical classifications (but per decision #3 we retire classifications, so narratives read `work_units.work_type` directly going forward).

## Architecture / file layout (new `src/lib/scoring/` package)

Pure, no I/O (unit-testable):
- `types.ts` — `Facts`, `ReviewFacts`, `Derived`, `WorkUnit`, `DimensionScores`, `ScoringConfig`, profile types.
- `facts.ts` — Zod schemas for the AI fact array (general + Review), exported for `callStructured`.
- `derivation.ts` — `derive(facts, derivationWeights): Derived` (difficulty/impact/execution_quality/novelty/risk/value per spec formulas, all thresholds/weights from `derivationWeights`).
- `rationale.ts` — `buildRationale(facts, workType): {impact_reason, quality_reason}` from templates keyed on true facts.
- `review.ts` — `reviewValue(reviewFacts, config): number` with the 4 substantiveness tiers and confirmed-valid multiplier; near-zero floor for rubber_stamp.
- `decay.ts` — `decayWeight(shippedAt, asOf, halfLifeDays)`.
- `scoring-engine.ts` — `scoreContributor(workUnits, overrides, rawEvents, config, decayProfile): DimensionScores`. Impact/Quality/Collaboration use soft-cap `cap * (1 - exp(-sum/cap))`; Consistency = pure timestamp math over raw_events (unchanged v1/v2 logic, factored out), no decay. No `confidence_scale`.
- `profiles.ts` — the 5 profile presets as plain data (`balanced` defaults; per-profile deltas, see below).
- `heuristic-fallback.ts` — fact correction + no-AI fallback; word-boundary regex; reuses `diff-facts.ts` path patterns.

I/O (thin, AI/DB):
- `aggregator.ts` — group `github_events` into `work_unit_candidates` by `correlation_key`; idempotent upsert.
- `diff-facts.ts` — extend existing module: add `getPushDiffFacts` (compare-commits) and a unified `getDiffForCandidate(candidate)` returning file list + content hash for AI input.
- `extract.ts` — `extractWorkUnits(candidate, diff, config): PersistedWorkUnit[]`. Calls OpenRouter `callStructured` with the fact-array schema; applies confidence policy; persists `work_units` + `work_unit_contributors`; writes `classification_cache`. Prompt per spec: segment diff first, facts per item, base on diff not title, `confidence` = fact certainty.
- `config.ts` — load `scoring_config` row for a repo (profile from `repositories.scoring_profile`, else `balanced`); resolve effective `derivation_weights`/`value_weights`/`caps`/`decay_half_life_days`.
- `seed.ts` — idempotent seed of the 5 profile presets at a `scoring_config.version` (e.g. `v3.0`).
- `outcome.ts` — `enrichOutcomes(repoId, contributorId?, opts)`: for shipped units with null/stale `outcome`, derive outcome facts (issue-closed referencing PR via `github_events.issue_closed` payload title/body regex for `#pr_number`/`closes #`; release containing commit via `release` events; incident via linked issue labels), write `outcome` + `outcome_updated_at`, re-run `derive` impact-outcome bonus, mark affected `dimension_scores` for rescore.
- `index.ts` — orchestration: `classifyRepo(repoId)` (aggregate → extract → persist units) and `scoreRepo(repoId, decayProfile)` (load units+overrides+events → engine → upsert `dimension_scores` for both profiles). `enrichAndRescore` wrapper for lazy-on-read.

### Profile presets (data in `profiles.ts`, persisted by `seed.ts`)

`balanced` (defaults):
- `value_weights = { impact: 0.5, execution: 0.3, difficulty: 0.2 }`
- `difficulty.scopeBase = {trivial:1,small:2,medium:3,large:4,system_wide:5}`; `+1 cross_cutting`; `+1 new_algorithm|new_subsystem`; `-1 boilerplate`.
- `impact.scopeBase = {trivial:1,small:2,medium:3,large:4,system_wide:5}`; `+1 user_visible`; `+1 breaking_change`; `outcome {issue_closed:+1, released:+1, unblocked:+1, cap:+2}`.
- `execution {testing_added:+1, documentation_updated:+1}`; `novelty {base:2, +2 new_algorithm|new_subsystem, +1 touches_architecture, -1 boilerplate}`; `risk {+1 each of touches_auth|touches_data_migration|touches_distributed_state, +1 breaking_change}`.
- `value` novelty bonus `+= min(0.1, noveltyBonusRate * norm(novelty))`; risk bump `+= min(0.05, riskBonusRate * (risk-1)/2)`. `noveltyBonusRate=0.1`, `riskBonusRate=0.1`.

Per-profile deltas (everything else inherits `balanced`):
- `product`: `impact.userVisibleBonus = 2`; `impact.outcome.released` weight stays `+1` but outcome `cap = 3`.
- `infrastructure`: `difficulty.crossCuttingBonus = 2`; `novelty.touchesArchitectureBonus = 2`; `execution.testingAddedBonus = 2`.
- `open_source`: `impact.documentation_as_user_visible = true` (treat `documentation_updated` as a `+1` impact signal); `execution.documentationBonus = 2`.
- `research`: `value_weights = { impact: 0.35, execution: 0.2, difficulty: 0.25 }` + add a `novelty` term to `value` (`value += 0.15 * norm(novelty)`, cap 0.15) — i.e. raise the novelty ceiling specifically for this profile. (Captured as a `value.noveltyTerm` config field present only in `research`.)

`caps` per dimension (soft-cap `C`): `impact: 100, quality: 80, collaboration: 60`, `consistency` unchanged (hard cap 50 from v1/v2). `composite` weights: `impact 0.4, quality 0.3, collaboration 0.2, consistency 0.1` (tunable via `scoring_config.caps.compositeWeights`).

## API / UI changes

- **`/api/repos/[owner]/[name]/scores` (modified):** returns `{ contributors: [{ contributor, current: DimensionScores, all_time: DimensionScores }], scoringConfigVersion }`. Query `?profile=current|all_time` for the default view; both always included.
- **`/api/repos/[owner]/[name]/work-units` (new):** `?contributor={id}` → per-unit explainable breakdown: `{work_type, summary, derived (stars), rationale, shipped, outcome, extraction_source, flagged_for_review}`. Powers the contributor detail page.
- **`/api/admin/review-queue` (new, gated to `sujalmh`):** lists `work_units WHERE flagged_for_review = true` with facts + rationale; supports `POST {work_unit_id, action: 'approve'|'reclassify'}` (reclassify sets candidate `needs_reclassification`).
- **Repo leaderboard page (`/repos/[owner]/[name]`):** current/all-time toggle; render `impact/quality/collaboration/consistency/composite` breakdown; keep podium + compact rows mapping to `composite` (current default). OG leaderboard route consumes the same `?data=` shape — update the page's `ContributorSlim` builder to the new dimension shape (the OG route itself needs no logic change, only the upstream mapping).
- **Contributor detail page (`/repos/[owner]/[name]/[contributor]`):** explainable per-unit list (stars + `rationale.impact_reason`/`quality_reason`); replace the old `classification` chip block.
- **Compare page:** adopt the new dimension shape.
- **Admin page:** add the review queue (reuse the existing `sujalmh` gate) + a per-repo profile selector (`POST /api/admin/scoring-profile`).
- **Narrative rewire:** `context.ts`/`fallback.ts` join `work_units` (via `source_event_ids`) instead of reading `e.classification`; `work_type`/themes come from `work_units`. The 5 narrative tasks' prompts unchanged in structure, only their input source changes.

## Phased task list (each independently testable + mergeable)

1. **Schema + seed.** Add the 7 tables + 3 columns to `initSchema()`; write `seed.ts` + run via `init-db.ts`; add `scoring_profile` default. *No behavior change yet.*
2. **Deterministic core (no AI, no DB).** `types.ts`, `facts.ts` (schemas), `derivation.ts`, `rationale.ts`, `review.ts`, `decay.ts`, `profiles.ts`, `scoring-engine.ts`. Full Vitest suite (see Validation). This is the spec's phases 2-3 and must pass with zero AI/DB.
3. **Aggregator + diff-facts (push compare-commits) + heuristic fallback.** `aggregator.ts`; extend `diff-facts.ts` (`getPushDiffFacts`, unified `getDiffForCandidate`, content hash); `heuristic-fallback.ts` (word-boundary). Backfill push `before`/`after` in `webhook-handlers.ts`. Unit-test aggregator grouping + heuristic fact-correction.
4. **AI extraction wiring.** `extract.ts` (OpenRouter `callStructured` with fact-array schema), confidence policy, `classification_cache`, persist `work_units` + `work_unit_contributors`. Works headless via heuristic fallback when no API key. Wire `classifyRepo` into the existing `/analyse` + `/initialize` pipeline (after aggregator).
5. **Review scoring.** Review fact schema + `reviewValue` tiers wired into `extract.ts` for `review_submitted` candidates; Layer-2 review-outcome bump for sibling PRs' Quality contribution.
6. **Scoring engine wiring + shape replacement.** `scoreRepo` writes both `current` + `all_time` `dimension_scores` rows. Replace `/scores`, repo leaderboard, compare, OG mapping, contributor detail with the new shape. Delete `computeContributionScore`/`normalizeScoreToImpact`/`WORK_TYPE_MULTIPLIER`. Rewire narratives (context.ts/fallback.ts) to `work_units`. **Single coordinated PR set** for the UI shape change to avoid a half-migrated frontend.
7. **Outcome enrichment (lazy-on-read).** `outcome.ts` + `enrichAndRescore`; call from the leaderboard/detail render path when `outcome IS NULL` or stale. Re-run impact outcome bonus; rescore affected contributor.
8. **Repository profiles + admin review queue UI.** Profile selector on admin page; review-queue page consuming `/api/admin/review-queue`. (Engine already profile-aware from step 2.)

## Validation (Vitest)

`test` script: `vitest run`; `typecheck`: `tsc --noEmit`. Required tests (per spec, all against pure modules unless noted):
- `derivation.test.ts`: difficulty/impact/execution/novelty/risk/value per spec; **difficulty-only (high difficulty, low impact) scores lower than the inverse** — the motivating example.
- `derivation.test.ts`: profile presets change `derived`/`value` as specified (product/infr/open_source/research deltas).
- `scoring-engine.test.ts`: a PR bundling 4 distinct changes → 4 `work_units`; sum-of-value across the bundle ≈ sum across 4 split PRs (not collapsed to one unit's worth), differing only in attribution/timing.
- `review.test.ts`: `rubber_stamp` near-zero (above floor); `blocking_issue_found + confirmed_valid` ≥ `2.5 × base`; `moderate` < `thorough` < `blocking+confirmed`; `blocking + not confirmed` = `1.2 × base`.
- `scoring-engine.test.ts`: **`extraction_confidence` alone (facts constant) does not change `dimension_scores`** — only `flagged_for_review`.
- `scoring-engine.test.ts`: identical `derived`, different `size_metrics` → identical scores (size never leaks).
- `scoring-engine.test.ts` (integration): after outcome facts populated, `impact`/score rises within the `+2` bonus cap; `computed_at` advances.
- `scoring-engine.test.ts`: two identical units, one recent, one > several half-lives old → materially different contribution under `current`, identical under `all_time`.
- `scoring-engine.test.ts`: malformed `created_at` in a raw_events fixture does not crash scoring for that contributor's remaining events.
- `rationale.test.ts`: rationale strings derive from true facts (template coverage).
- `heuristic-fallback.test.ts`: `\bfix\b` does not match "debug"; `testing_added` detected from test file paths; `touches_auth` from `auth/`/`session/`/`login/` paths.
- `aggregator.test.ts`: PR/push/review/issue grouping into candidates with correct `correlation_key`.
- `config.ts`/`seed.ts`: round-trip a profile through the resolver.

Manual smoke (dev, after AI wired): run `/analyse` on a real repo; verify `work_units` rows (1-N per PR), `dimension_scores` current/all_time, leaderboard toggle, contributor per-unit breakdown, admin review queue populates for low-confidence units, outcome enrichment triggers on read.

## Risks

1. **Big-bang shape change** (decision #2) can briefly break the leaderboard/compare/OG mid-rollout. Mitigate: land steps 2-5 (engine + tests + extraction) first with no UI change; step 6 is one coordinated PR replacing `/scores` + all four consumers + deleting the old module, deployed together.
2. **Narrative rewire** (decision #3) touches 5 AI tasks' input path. If `work_units` are absent for a repo (not yet classified), narratives must degrade gracefully (treat as no work_type, not crash) — `context.ts` must tolerate missing units.
3. **Compare-commits diff size / rate limits** for large pushes (decision #5): cap files per compare (`MAX_FILES_PER_PR` equivalent), time out at 10s, fall back to commit-message heuristics on failure; legacy pushes without `before`/`after` skip extraction (Consistency still works).
4. **Lazy-on-read write under a GET** (decision #4): enrich+rescore writes to `work_units`/`dimension_scores` during a page render. Keep it bounded (one contributor per request, stale-check cheap via the `wu_outcome_idx` index), and tolerate concurrent renders (idempotent upserts). If the write is too slow, the render returns last-known scores and a follow-up request picks up enrichment.
5. **Neon `BIGINT[]` + JSONB** usage is new here (arrays on `source_event_ids`); verify the serverless driver handles `INTEGER[]`/`BIGINT[]` literals — if not, store as `JSONB` arrays instead (schema already mostly JSONB-friendly). Confirm during step 1.
6. **Next 16 breaking changes** — per `AGENTS.md`, read `node_modules/next/dist/docs/` before editing route handlers (`params` is a Promise here; heed deprecation notices). Applies to the modified/new API routes.
7. **`work_type` enum shrink** (9 vs v2's 13) — any persisted v2 `classification.work_type` values that no longer exist are only read during the one-time narrative rewire transition; after rewire they're unused. No data migration needed since we retire the column from the read path (drop is out of scope; leave the column in place, stop reading it).

## Out of scope

- Multi-author attribution (co-authors, review-requested weight) — table-ready, not populated.
- Scheduled/cron outcome enrichment (lazy-on-read only, per decision #4).
- Per-repo custom `derivation_weights` overrides beyond the 5 presets.
- Push diff beyond compare-commits (no patch-level AI re-segmentation of enormous monorepo pushes beyond the file cap).
- A `typecheck` script beyond `tsc --noEmit` added here (it is in scope — added per decision #1).
- Dropping `github_events.classification`/`classified_at` columns (stop reading; leave for audit).
- Migration framework (keep idempotent `initSchema`).
- Annual/seasonal decay variants; cross-repo leaderboards.

## Open questions / veto points (assumed; push back if wrong)

- **Decay half-life default = 60 days** (tunable via `scoring_config.decay_half_life_days`). Adjust if the "current" view should fade faster/slower.
- **No hard decay window** — `current` decays over *all* shipped units as_of now (the half-life makes old units negligible rather than a hard cutoff). If you want a hard trailing window (e.g., 180 days) instead, say so.
- **Admin review-queue UI ships in this iteration** (step 8). If API-only is preferred, drop the admin page additions.
- **Profile composite weights** (`impact 0.4 / quality 0.3 / collaboration 0.2 / consistency 0.1`) — confirm or tune.
